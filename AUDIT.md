# SentinelPay audit and remediation

Date: 16 November 2026. Scope: application/shared code, database migrations, dependencies, deployment/CI configuration, historical exposure, and legacy Solidity tooling. This records source review and executed checks, not an independent security certification.

## Product and trust boundaries

SentinelPay provides merchant USDC invoices on Solana. The server fixes the network, mint, recipient, amount, and expiry. Customers sign transactions, funds go to merchant wallets, and finalized RPC receipts determine settlement. Balances and invoice revenue are separate. The reserve assistant applies deterministic rules to balances and saved expenses/reserves; it does not predict returns or verify identity.

Next.js proxies supported endpoints to Express using a private credential. Express stores sessions, invoices, attempts, incoming receipts, refunds, treasury trades, and audit events in PostgreSQL. PGlite supports development. Solidity is a separate legacy HashKey experiment. The historical Rust workspace has no program source; neither secures Solana checkout.

## Operational limits

1. **Live integrations:** hardware/mobile/extension wallet behavior, funded devnet settlement, live Jupiter routes, and issuer eligibility/redemption are outside this automated stage by user choice. Before enabling live swaps, verify mint, provider contract, fees, liquidity, and exact invoice credit. [Jupiter migration](https://developers.jup.ag/docs/swap/migration/metis-to-build).
2. **Production operations:** configure origin/network/RPC, private provider/proxy credentials, verified PostgreSQL TLS, dedicated database role, backups/restores, monitoring, and explicit migrations before startup. Supported topology is one API process; scaling needs shared rate limits and reconciliation coordination. Remote CI execution is not claimed.
3. **Receipt recovery:** constraints prevent duplicate revenue, not arbitrary transfers to wallets. Every verified incoming transfer is journaled, including extra payments after settlement. Completed attempts are revisited for 24 hours; older exceptions require archival lookup. Empty RPC indexes do not prove non-settlement. Monitor unresolved attempts/refunds and provider indexing. Uncertain refunds cannot be blindly replaced; older pending refunds require investigation.
4. **Accounting:** this is an invoice/refund ledger, not a journal of all external transfers, fees, tax events, treasury valuations, or yield. CSV is a page export. Refunds need merchant USDC and SOL fees. Swap payers receive USDC refunds, not reversal of the original swap or fees.
5. **Treasury/legacy:** keep treasury disabled until provider eligibility, mint, liquidity, and exit restrictions are reviewed. A checkbox does not establish KYC/issuer approval. Existing EVM deployments need separate authority/bytecode review; contracts distribute native HSK and do not acquire USDY. [Ondo USDY](https://ondo.finance/usdy).
6. **Historical exposure:** no account, owned token accounts, or upgrade authority was found on the networks checked, and the exported OIDC token had expired. This does not establish that the key never held an unrelated external role. History still contains retired material. Never reuse it; coordinate any future history rewrite. [Exposure review](security/EXPOSURE_REVIEW.md).

No production deployment, funded payment, external credential mutation, or Git history rewrite was performed.
